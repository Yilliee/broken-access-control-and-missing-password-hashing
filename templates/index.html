Vulnerability Demo Site

An intentionally insecure Flask application that demonstrates Missing Password Hashing and Broken Access Control (both accidental and explicit).

Register Login Admin Panel (no auth!) /api/users (no auth!)

Vulnerabilities Demonstrated

VULNERABILITY 1 Missing Password Hashing

When a user registers, their password is saved to the SQLite database exactly as typed – no hashing, no salting. Login also compares the raw plaintext values.

Vulnerable code (app.py – register route): 
# password saved without hashing
db.execute(
    "INSERT INTO users (username, email, password, role) VALUES (?, ?, ?, ?)",
    (username, email, password, "user"),
)
Secure alternative: 
from werkzeug.security import generate_password_hash, check_password_hash

hashed = generate_password_hash(password)   # bcrypt under the hood
db.execute("INSERT INTO users ... VALUES (?, ?, ?, ?)", (..., hashed, ...))

Impact: If the database is compromised, every user's password is immediately readable. Passwords are often reused across sites, so a single breach exposes accounts elsewhere.

VULNERABILITY 2 Broken Access Control – Accidental (IDOR on profile page)

The profile route /profile/<id> checks that the visitor is logged in, but forgets to verify that the logged-in user is the owner of the requested profile. Any authenticated user can view any other user's private profile by changing the number in the URL.

Vulnerable code (app.py – profile route): 
@app.route("/profile/<int:user_id>")
def profile(user_id):
    if "user_id" not in session:      # ✓ checks login …
        return redirect(url_for("login"))
    # ✗ missing ownership check – any user can access any profile!
    user = db.execute("SELECT * FROM users WHERE id = ?", (user_id,)).fetchone()
Secure alternative: 
if session["user_id"] != user_id and session["role"] != "admin":
    abort(403)

Try it: Log in as alice / alice1234 then visit /profile/1 (the admin account).

VULNERABILITY 3 Broken Access Control – Accidental (privilege escalation via role change)

The /change-role endpoint checks that the requester is logged in but never checks whether they are an admin. Any regular user can promote themselves to admin by submitting the form (or crafting a direct POST request).

Vulnerable code (app.py – change_role route): 
if "user_id" not in session:   # ✓ checks login …
    return redirect(url_for("login"))
# ✗ missing admin check – any logged-in user can change anyone's role!
db.execute("UPDATE users SET role = ? WHERE id = ?", (new_role, target_user_id))
Secure alternative: 
if session["role"] != "admin":
    abort(403)

Try it: Log in as alice / alice1234 and use the role-change form on the Dashboard to make yourself admin.

VULNERABILITY 4 Broken Access Control – Explicit (unprotected admin panel)

The /admin route was explicitly coded without any authentication check. Any anonymous visitor who knows (or guesses) the URL has full access to the admin panel and can see all users.

Vulnerable code (app.py – admin route): 
@app.route("/admin")
def admin():
    # No auth check at all – anyone can reach this page
    users = db.execute("SELECT * FROM users").fetchall()
    return render_template("admin.html", users=users)
Secure alternative: 
if "user_id" not in session or session["role"] != "admin":
    abort(403)

Try it: Open /admin without logging in.

VULNERABILITY 5 Broken Access Control – Explicit (unauthenticated API leaking passwords)

The /api/users JSON endpoint was deployed without any authentication check and returns all user records including plaintext passwords. This combines Vulnerability 1 and Vulnerability 4.

Vulnerable code (app.py – api_users route): 
@app.route("/api/users")
def api_users():
    # No auth check; returns plaintext passwords
    users = db.execute("SELECT * FROM users").fetchall()
    return jsonify([dict(u) for u in users])
Secure alternative: 
# Require admin session AND never expose the password column
if "user_id" not in session or session["role"] != "admin":
    abort(403)
users = db.execute("SELECT id, username, email, role FROM users").fetchall()

Try it: /api/users – no login needed.
